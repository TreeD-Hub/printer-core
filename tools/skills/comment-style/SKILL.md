# Comment Style

## Обзор

Проверять и стандартизировать комментарии в любых целевых каталогах на основе project-конфига.
При задаче «причесать комментарии» менять только комментарии/документацию/пустые строки.

## Workflow

### Шаг 1. Прочитать профиль репозитория

- Брать настройки из `.codex/repo-standards.yaml`.
- При отсутствии профиля использовать встроенные безопасные значения.

### Шаг 2. Запустить проверку стиля

```bash
python skills/comment-style/scripts/check_comment_style.py --root <repo-root>
```

Опционально:

```bash
python skills/comment-style/scripts/check_comment_style.py --root <repo-root> --paths path1 path2 --config .codex/repo-standards.yaml --max-header-lines 40
```

### Шаг 3. Исправить только целевые замечания

- Ожидаемые коды: `MISSING_HEADER`, `MISSING_PURPOSE`, `MISSING_CONTOUR`, `MISSING_BLOCK_MARKER`.
- Не менять runtime-логику при задачах на формат комментариев.

## Примеры триггеров

- `Приведи комментарии в scripts/** к единому формату.`
- `Добавь шапки и блоки в shell-файлы, не меняя поведение.`
- `Проверь покрытие комментариев по моему профилю.`
