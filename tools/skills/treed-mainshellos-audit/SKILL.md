# Treed Mainshellos Audit

## Обзор

Проводить технический аудит только по фактам, без правок рабочих файлов.
Считать этот skill источником аудитного контракта для репозитория `treed-mainshellOS`.

## Workflow

### Шаг 1. Определить режим и границы

- Считать задачу аудитом, если пользователь просит проверить, ревьюить или оценить код/конфиги/документацию.
- Включить режим read-only: не редактировать файлы, не менять git-историю, не выполнять разрушительные действия.
- Ограничить анализ запрошенными файлами и соседними зависимыми конфигами.

### Шаг 2. Собрать доказательства

- Читать исходники и конфиги точечно, не перегружая контекст.
- На каждое замечание фиксировать доказательство в формате `path:line`.
- Для поиска использовать `git grep`.

### Шаг 3. Пройти проектный чеклист

- Использовать полный чеклист: [references/audit-checklist.md](references/audit-checklist.md).
- Обязательно проверять:
  - `loader/**`: идемпотентность шагов, fail-fast для критичных сервисов, корректный best-effort для опциональных.
  - `klipper/**` и `moonraker/**`: ownership/source-of-truth конфигурации.
  - `docs/**` и `README.md`: соответствие фактическому коду и структуре каталогов.
  - `loader/**`, `runtime-scripts/**`, `moonraker/**`, `plymouth/**`, `tools/**`: соответствие формату комментариев проекта.

### Шаг 4. Проставить приоритеты

- `P0`: критичная поломка базового сценария, риск потери работоспособности или данных.
- `P1`: высокий риск регрессии или недетерминированного поведения.
- `P2`: поддерживаемость, читаемость, неполнота документации, не критичная логическая уязвимость.

### Шаг 5. Вернуть отчет

- Писать на русском, коротко и технически точно.
- Вывести findings в порядке `P0 -> P1 -> P2`.
- Для каждого finding использовать шаблон:

```text
[P?] Краткий заголовок
- Факт: ...
- Риск: ...
- Действие: ...
- Доказательство: path/to/file:line
```

- Если замечаний нет, явно написать `Findings не обнаружены` и указать остаточные риски/непроверенные зоны.
- В конце коротко зафиксировать ограничения проверки (например, что не запускалось локально на Windows без WSL).

## Примеры триггеров

- `Сделай аудит loader/steps и проверь, нет ли silent skip.`
- `Проведи ревью изменений в klipper профиле treed_v2_corexy_v1.`
- `Проверь конфиги moonraker и документацию на несоответствия.`
