# Архитектура обновлений TreeD

## Что работает в этом срезе

Moonraker принимает запрос, но не владеет долгой операцией. Он передаёт проверенные аргументы fixed root-команде; systemd worker владеет последовательностью, блокировкой и итогом. Frontend может восстановить operation после перезагрузки страницы, Moonraker или UI-службы.

Для `printer-ui` worker скачивает точный release asset, сверяет SHA-256 с полем `digest` GitHub Release API, проверяет ZIP и manifest, публикует каталог, перезапускает `treed-shell.service` и требует три успешные локальные HTTP-проверки. До успешной проверки прежний UI остаётся в operation-specific каталоге отката. Ошибка публикации, readiness или остановка worker вызывает попытку восстановления; boot recovery возвращает старый каталог, когда он сохранён, либо подтверждает точный target manifest и HTTP readiness, если публикация уже завершилась.

Контрольная сумма GitHub защищает от повреждения или подмены при загрузке при доверии к GitHub API и TLS. Она не является отдельной подписью издателя. Политика независимой проверки подписи UI-пакета остаётся незавершённой.

## API и операция

`POST /server/treed/update/apply` принимает `requestId`, `targetId` и `targetTag`. `requestId` — UUID; старые клиенты без поля получают UUID от сервера. Успешный ответ быстро сообщает `accepted`, `operationId`, `status`, `phase`, `progress`, `message`, `targetId` и `targetTag`. Повтор того же `requestId` возвращает существующую операцию. Другой запрос не заменяет занятую очередь.

`GET /server/treed/update/status` читает локальное состояние и не делает сетевой refresh или firmware inventory. Старые поля ответа сохранены; добавлены `operation`, `latestOperation`, `history`, `status`, `phase`, `progress` и `resultCode`. `GET /check` параллельно проверяет релизы с таймаутом 7 секунд на источник. Проверка live MCU остаётся на `/firmware`.

Активные статусы: `queued`, `validating`, `downloading`, `installing`, `restarting`, `verifying`, `rolling_back`. Terminal статусы: `applied`, `rolled_back`, `error`, `rejected`. `progress` равен 0 в очереди, неизвестен (`null`) без измеримой метрики и равен 100 только после подтверждённой готовности UI.

Root-служба атомарно хранит текущую операцию и последние десять завершённых в `/var/lib/treed-update/state.json`; inter-process `flock` сериализует submit, worker и recovery. Файл синхронизируется на диск до замены, каталог — после неё. Systemd path-unit запускает worker при изменении состояния, закрывая промежуток между записью queued и запуском службы. `ExecStopPost` и boot recovery завершают состояние, если worker прервался.

## Чего пока нет

Обновление `printer-core` намеренно недоступно (`canApply=false`, capability `ab_update_backend_incomplete`). Этот репозиторий не содержит подтверждённой разметки устройства, интеграции загрузчика, production RAUC system bundle, ключа подписи, миграции постоянных данных или обязательной post-boot health-проверки. Старый путь `git checkout` плюс обычный loader удалён из updater: он не мог дать A/B откат.

`treed-ab` сейчас только сообщает fail-closed состояние. Установка RAUC или наличие platform attestation сами по себе не разблокируют кнопку. Для включения требуются все следующие части:

1. Зафиксировать модели плат, загрузчик, схему разделов, объём накопителя и способ восстановления.
2. Собрать неизменяемый системный bundle со всеми компонентами, compatibility manifest и подписью; проверять подпись до записи.
3. Реализовать запись только неактивного слота и ограниченные попытки загрузки; исходный подтверждённый слот сохранять.
4. Разделить системные файлы и пользовательские данные, подготовить миграцию настроек с возможностью возврата.
5. Проверить на целевой плате загрузку, службы, обязательные MCU, интерфейс и стабильность; подтверждать новый слот лишь после health gate.
6. Испытать потерю питания на каждой границе, ошибку записи, повреждённый пакет, отказ платы, rollback и восстановление через сервисный носитель.
7. Только после этого выставлять capability `supported=true` и разрешать системные выпуски.

Обновление прошивки MCU остаётся отдельной операцией: возврат OS-слота не откатывает прошивку контроллера. Выпуск системы должен явно объявлять совместимость с установленными версиями MCU.

## Проверки

`tools/tests/test_treed_update_component.py` проверяет совместимость POST, быстрый локальный status и capability. `tools/tests/test_treed_update_service.py` проверяет idempotency, busy, валидацию аргументов, durable state, service-start failure, прерывание и recovery UI в изоляции. Эти проверки не заменяют испытания systemd, RAUC и загрузчика на целевой плате.
