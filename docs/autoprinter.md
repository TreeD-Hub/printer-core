# AutoPrinter на стороне принтера

Этап 1 добавляет локальное долговременное хранилище, явное связывание аккаунта и приём изменений очереди. Компонент не выполняет печать и не оценивает модель.

## Включение

Секция `[treed_autoprinter]` в `moonraker/base/00-core.conf` по умолчанию выключена. Перед включением задайте `printer_id`, `profile_id`, `api_origin`, `credentials_path` и `storage_path`. Origin должен быть HTTPS без пути, query и fragment. Credential-файл содержит ровно `printer_id` и `secret` в JSON; в POSIX-системе файл должен быть доступен только владельцу. Не сохраняйте credential в репозитории, Moonraker-конфиге или журнале.

Если секция включена без корректной конфигурации, компонент остаётся загруженным и сообщает `configured: false`. Он не создаёт API для чтения локальных файлов. Для штатного связывания используйте авторизованный `POST /server/treed/autoprinter/pairing`, введите возвращённый краткоживущий код в интерфейсе аккаунта и проверьте `binding_state` через `GET /server/treed/autoprinter/status`. Код не содержит credential и после истечения срока не действует.

## Синхронизация

Компонент отправляет ограниченные снимки состояния и повторяет доставку сохранённых результатов команд после сетевых сбоев и перезапуска. `binding_state` хранится отдельно от состояния связи. При `control_epoch_mismatch` компонент применяет новое состояние binding, затем синхронизируется снова без подтверждения старых результатов.

Скачанный asset проверяется по размеру и SHA-256 и сохраняется в `storage_path`. Backend получает receipt только после успешной durable-записи. Если ответ на receipt потерялся и backend перестал рекламировать передачу, компонент повторно отправляет локальную запись из `pending_receipts`. Новая привязка использует отдельный namespace; данные прежней привязки сохраняются на диске, но не входят в текущую очередь.

Если локальный журнал очереди и серверная ревизия не позволяют доказать, что очередь восстановлена, компонент блокирует дальнейший sync и показывает `queue_recovery_required`. На этом этапе нет команды автоматического сброса или восстановления: сначала сохраните локальный каталог AutoPrinter и сверьте его с backend вручную. Компонент не принимает новую пустую очередь как замену потерянной.

## Границы этапа

- Очередь постоянно приостановлена; даже `pause_queue` не запускает физическое действие.
- Команды, связанные с запуском, движением, нагревом, паузой печати, остановкой после задания, отменой и проверкой стола отклоняются.
- Компонент не ищет задания в Klipper или Moonraker, не использует `job_queue`, file manager, shell или G-code.
- Нет endpoint для чтения, перечисления или загрузки сохранённых файлов. Нет локального переноса файлов в каталог печати.
- Нет model inference и нет физической готовности. `ready` и capability `bed_check` всегда равны `false`.
- Отзыв credential обнаруживается только при следующей успешной попытке связи; офлайн-принтер не может узнать об отзыве немедленно.

Адресная проверка без сети и устройства: `python -B tools/tests/test_treed_autoprinter_component.py`. Loader доставляет локальное хранилище, компонент и транспорт, затем требует успешной загрузки компонента, даже когда feature выключен.
