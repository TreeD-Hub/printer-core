# Диагностическая проверка стола AutoPrinter

Проверка пустых кадров, дообучение, состояние «стол чист» и автосъём остаются
в [отдельном TODO](autoprinter-todo.md). Их нужно завершить до допуска к печати.

`E0BedChecker` — локальный кандидат для поиска детали на кадре стола. Он нужен для диагностической команды `recheck_bed`; результат не разрешает физический запуск и не завершает выполняемое задание. Переключатель проверки по умолчанию включён; для работы нужны модель и её Python-окружение.

## Ограничение модели

Используется RF-DETR Small E0 из `printer-defect-server/models/releases/fdm-preprocessing-20261016/detection/E0/training_5epochs/checkpoint_best_total.pth`.

| Параметр | Значение |
|---|---|
| Версия | `fdm-detail-e0-20261016-8de7e8aa22e2` |
| Размер файла | `127479855` байт |
| SHA-256 | `8de7e8aa22e20893a563c0c04d28f0019dcad9ef8d805818df6fd2ec8b10866e` |
| Вход | исходный RGB кадр, `512×512` |
| Класс | `0` — деталь |
| Порог score | `0.5191324353218079` |
| NMS | `0.8` |
| Окружение inference | `rfdetr==1.11.0`, `torch==2.11.0`, `torchvision==0.26.0`, `Pillow==12.3.0` |

Имя класса в этом checkpoint повреждено кодировкой при обучении. Служба строго
сверяет его с `checkpoint_class_names` в закреплённом manifest; исходный
`training_config.json` содержит ту же последовательность символов. Класс `0`
по-прежнему означает деталь. Весовой файл и его SHA-256 не менялись.

В тестовой выборке были 818 размеченных деталей: 806 обнаружены, 12 пропущены. Все кадры содержали детали; отрицательных кадров пустого стола нет. Поэтому обнаружение класса `0` возвращает `occupied`, а отсутствие обнаружений, ошибка модели или недостоверный кадр возвращают `unknown`. E0 никогда не возвращает `empty` и не квалифицирован для допуска к печати. Нельзя подменять эту модель классификатором спагетти, COCO-весами, другой версией или выбранным на тестовой выборке порогом.

## Настройка

Проверку выполняет отдельная служба `treed-vision` через приватный Unix-сокет. Она использует общее окружение моделей вне Python-окружения Moonraker. Шаг `loader/steps/treed-cam.sh` принимает проверенные локальные артефакты и закреплённый runtime; автоматической загрузки модели из сети и возврата к облачному анализу нет. Параметры установки описаны в [runtime службы](../runtime-scripts/treed-vision/README.md).

В `[treed_autoprinter]` задайте:

| Параметр | Значение |
|---|---|
| `bed_check_socket` | приватный сокет службы; default `~/treed/vision/run/vision.sock` относительно домашнего каталога пользователя Moonraker |
| `bed_check_snapshot_url` | локальный адрес снимка; default `http://127.0.0.1:8080/?action=snapshot` |

Проверка стола и локальное исполнение включены без фича-флагов; отсутствие или ошибка службы закрывает проверку. Компонент создаёт checker без открытия камеры и тяжёлых импортов. При проверке он получает локальный JPEG и передаёт его службе с контекстом задания и `bed_epoch`. Служба работает на CPU и не имеет команд управления принтером.

Доставка Moonraker включает `treed_autoprinter_bed.py` и общий `treed_vision_client.py`. Старый `treed_autoprinter_bed_inference.py` не используется в рабочем пути проверки стола. Параметры `bed_check_model_path` и `bed_check_python` сохраняются для совместимости конфигурации; они не выбирают модель или интерпретатор общей службы.

Служба рассчитана на Linux: после проверки checkpoint она передаёт модели путь через `/proc/self/fd`. На Windows реальный inference не поддержан. Модель E0 загружается при смене режима после завершения предыдущего worker; холодный результат не используется как доказательство свежего состояния стола. Короткий ресурсный тест на плате пройден; [результаты и ограничения](local-vision-acceptance.md) не заменяют приёмку во время печати.

Проверка получает новый кадр для каждого запроса, ограничивает размер ответа и принимает только JPEG. Запрос не использует cookies, credentials, redirects или proxy. Время получения ответа не доказывает свежесть сенсора: непустой `Age`, ошибка камеры и недостоверные данные дают `unknown`. Успешный inference также не доказывает, что физический стол пуст.

Захват удаляет до семи нулевых байтов, которыми камера дополняет JPEG после маркера EOI. Более длинный или ненулевой хвост отклоняется; лимит размера проверяется до удаления padding.

## Повторная проверка и статус

Авторизованный `POST /server/treed/autoprinter/control` принимает `{"type":"recheck_bed"}`. Действие доступно при подключённом компоненте и paired-состоянии, в том числе при недоступном адаптере принтера. `occupied` и `unknown` сохраняются в локальном durable-журнале; если задание находится в `verifying`, эти результаты его не завершают. Только квалифицированный провайдер может вернуть пригодное для завершения `empty`.

`GET /server/treed/autoprinter/status` показывает безопасную диагностику `bed_check` только при paired-состоянии. Снимок для backend сохраняет прежнюю форму, а `capabilities.bed_check` остаётся `false`. Endpoint не принимает доказательства или команды inference.

Backend по умолчанию не разрешает версии моделей: `allowed_model_versions` остаётся пустым, пока deployment отдельно не настроит allowlist. Для сопоставления этой версии потребуется `fdm-detail-e0-20261016-8de7e8aa22e2`; само добавление версии не меняет ограничение `live_qualified=false`.

## Граница допуска к печати

E0 не подтверждает пустой стол, поэтому не может разрешить начало печати или завершить задание. Установка весов, положительное обнаружение детали и успешный тест на кадрах с деталями не меняют этот запрет. Для квалификации потребуется отдельная выборка пустого стола, проверка ложных допусков и явное изменение контракта; эти действия отложены.

Адресные офлайн-проверки интеграции перечислены в [`tools/tests`](../tools/tests/README.md). Они используют подставные checker и runtime; реальные веса и устройство в них не участвуют.
