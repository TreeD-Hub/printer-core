# AutoPrinter: оставшиеся задачи

Этот список фиксирует работу после диагностического этапа E0. Отсутствие
проверки пустых столов — незавершённая задача, которую нужно закрыть данными
и испытаниями. Текущий запрет `empty` сохраняется до этой приёмки.

## Пустые кадры и дообучение E0

- [ ] Собрать кадры действительно пустого стола с камеры принтера: разные
  освещение, положение платформы, PEI, следы клея, блики и загрязнения.
  Пустые кадры не исключать из датасета. Для детектора это отрицательные
  примеры с пустой разметкой, а не новая фиктивная рамка вокруг стола.
- [ ] Сохранить в выборке занятые столы: нормальные детали, небольшие остатки,
  тонкие и прозрачные изделия, мусор и частично снятые детали. Чёрный кадр,
  перекрытая камера, размытое или старое изображение не считать пустым столом.
- [ ] Разделить train/validation/test по съёмочным сессиям и принтерам до
  дообучения, чтобы соседние кадры не попадали в разные части. Закрепить
  происхождение кадров и проверить, что пустые примеры проходят весь pipeline.
- [ ] Оценить текущую E0 на такой выборке, затем дообучить её с отрицательными
  примерами и сравнить результаты на неизменяемом test-наборе. Порог выбирать
  по validation, не подстраивать по test.
- [ ] Отдельно измерить ложное «стол чист» на занятых столах, ложную занятость
  на пустых и долю `unknown`. Согласовать допустимую частоту ложного допуска;
  общая accuracy или recall обнаружения деталей её не заменяют.
- [ ] Проверить время, RAM и устойчивость inference на целевом компьютере
  принтера. Выпустить новый immutable artifact с версией, SHA-256, классами,
  параметрами и отчётом проверки; старые веса не перезаписывать.

## Три состояния стола

- [ ] Добавить в алгоритм квалифицированный результат «стол чист» — `empty`.
  Wire-контракт уже содержит `empty`, `occupied` и `unknown`; четвёртое значение
  `clean` или отдельный флаг готовности вводить не нужно.
- [ ] Для `empty` подтвердить область обзора стола, свежесть и качество кадров.
  По результатам валидации выбрать число кадров, интервалы и пороги. Простое
  отсутствие рамок E0 не считать достаточным основанием.
- [ ] Проверить одноразовый допуск с `check_id`, `after_run_id`, `bed_epoch`,
  boot ID и TTL: старый кадр, рестарт, ручное вмешательство и смена поколения
  не должны разрешать следующий запуск.
- [ ] Только после приёмки подключить квалифицированную модель в core и
  согласовать backend allowlist/capability. Обе ошибки — `occupied` и `unknown` —
  должны сохранять блокировку. Кнопка «считать стол пустым» не нужна.

## Алгоритм автосъёма

- [ ] Дописать сценарий для существующего PEI-прототипа через действующий
  цикл завершения печати. Перед реализацией сверить реальные макросы,
  датчики, кинематику и приоритет настроек серии/G-code; не создавать второй
  механизм после `END_PRINT`.
- [ ] Описать и реализовать переходы `cooling → removing → verifying`, условия
  входа и завершения, таймауты, отмену и восстановление после перезапуска.
  Температуры, перемещения и усилия брать из отдельной аппаратной калибровки.
- [ ] Ограничить число попыток. Не повторять движение после неопределённого
  результата; занятый стол, ошибка механизма или камеры требуют остановки
  очереди и вмешательства оператора.
- [ ] После съёма получать новые кадры. Завершение макроса не означает `empty`;
  следующее задание возможно только после квалифицированной проверки стола.
- [ ] Сначала проверить переходы на offline-сценариях, затем провести отдельно
  разрешённую аппаратную приёмку с возможностью штатной локальной остановки.

Установка ML-зависимостей, реальный inference, дообучение и аппаратная приёмка
отложены по текущим ограничениям работы. Настройка диагностической E0 описана
в [проверке стола](autoprinter-bed-check.md), текущее поведение — в
[AutoPrinter](autoprinter.md).

## Ёмкость очереди и истории

- [ ] Согласовать лимит запусков и срок хранения завершённой истории с backend.
  Текущий `max_runs` учитывает и историю; до решения не удалять записи или
  dedup-команды автоматически и при достижении лимита отклонять новые задания.
