# Локальное зрение: состояние реализации и приёмки

Реализация затрагивает `printer-core`, `printer-ui` и `treed-back`.
Отчёт фиксирует локальную приёмку; push и production deploy не выполнялись.
Рабочие службы принтера не заменялись. На ROCK Pi запускались только временные
диагностические процессы, без движения, нагрева, запуска печати и PAUSE.

## Программный контур

- `treed-vision` выполняет CPU inference в отдельном процессе. Общение с локальными
  адаптерами идёт через приватный Unix-сокет. При смене модели предыдущий worker
  завершается; результаты подтверждают контекст запроса и поколение worker.
- Детекция сохраняет блокировку серии до запроса PAUSE и проверяет состояние
  принтера. Обычный RESUME не разрешает следующие задания. Неизвестный результат
  анализа сбрасывает подтверждения дефекта.
- Пакет использует существующие assets, серии, запуски и SQLite-журнал. Все файлы
  проверяются до атомарного принятия. Повторная доставка и потеря подтверждения
  не создают новые запуски; timeout доставки не освобождает резервирование backend.
- UI различает текущую печать и серию, показывает причину блокировки и локальный
  результат анализа. JPEG для просмотра запрашивается у принтера явно.
- Loader и updater доставляют общий runtime, сохраняют локальные настройки и
  credentials. Модели устанавливаются из локальных артефактов с проверкой SHA-256.

Контракты описаны в [AutoPrinter](autoprinter.md),
[проверке стола](autoprinter-bed-check.md) и
[README vision runtime](../runtime-scripts/treed-vision/README.md).

| Backend package API и sync | PHP lint девяти файлов; 6 PHPUnit-сценариев, 46 assertions |
| Updater, атомарная доставка и rollback | 50 тестов прошли |

| Loader shell | `bash -n` четырёх изменённых скриптов прошёл |

Backend проверялся в существующем PHP 8.2.33 Docker image, без сети, с SQLite
`:memory:` и временным storage. Рабочая БД не использовалась. Независимое ревью
повторно проверило исправления статуса, отмены остатка пакета, TTL/boot доставки
и повторов одного asset в порядке A–B–A; оставшихся P1/P2 в этом объёме не найдено.

Отдельный прогон component/device/store выявил известное до задачи падение
`test_sync_after_lost_unlink_confirm_rotates_outbox_before_new_binding`.
Падение подтверждено на исходной ревизии и не исправлялось в этой задаче. Три устаревших ожидания новых
defaults и capability исправлены и перепроверены отдельно.

## Измерения на ROCK Pi

Устройство: ROCK Pi 4B+, Debian 12 ARM64; Klipper ready, print standby,
virtual SD не активна, operation phase idle. На время тестов применялись и
проверялись CPUQuota 150%, MemoryMax 1536 MiB, swap 0, Nice 10 и два ML-потока.
Стенд прекращает работу при 80 °C или выходе принтера из состояния покоя.
Кадры не сохранялись и не покидали принтер.

Повторный тест исправленного runtime завершился успешно за 57,388 с:

| Режим | Прогрев и первый свежий результат | Два свежих кадра |
|---|---|---|
| Spaghetti v12 | 12,39 с | 1370,4 / 1339,1 мс |
| Bed E0 | 34,27 с | 7416,9 / 7256,1 мс |

Пик памяти всего теста — 636,6 MiB, температура — 76,875 °C; CPU time —
69,46 с. E0 вернул `occupied`. Klipper оставался ready/standby/idle до,
во время и после проверки. Временная служба завершилась с кодом 0 и перешла
в inactive/dead. Это короткое измерение в покое, а не доказательство
качества моделей или производительности во время печати.

Первоначально E0 отклонялся после загрузки: метка класса в checkpoint сохранена
с повреждённой кодировкой. SHA-256 совпал с закреплённым выпуском; исходный
`training_config.json` содержит ту же метку. Runtime строго сверяет её с
`checkpoint_class_names` закреплённого manifest; проверка хеша не ослаблена.
При первоначальной диагностике пик температуры достиг 79,375 °C, поэтому
тепловой запас требует отдельного длительного измерения.

## Незакрытые условия допуска

Пользователь подтвердил отсутствие набора пустых, занятых и недостоверных кадров.
E0 остаётся диагностическим: только `occupied` или `unknown`. Он не выдаёт
`empty`. `execution_enabled` остаётся `false`.

До допуска автономной серии нужны квалификация пустого стола, аппаратная
приёмка снятия детали и паузы, измерение границы 30 секунд под нагрузкой,
устойчивости температуры и влияния inference на Klipper. Полный сценарий
пакета с отключённой сетью и перезапуском устройства проверен программными
тестами, но не физической печатью.

Production rollout требует согласованной доставки core/UI/backend и миграции
пакетов в базе AutoPrinter. Полный test suite, build, e2e и визуальная проверка
не запускались. Сохранение disabled-режима не означает завершение аппаратной приёмки.
