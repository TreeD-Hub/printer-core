# Режимы XYZ и обдува драйверов

Два независимых публичных макроса управляют XYZ и обдувом:

- `TREED_UI_SET_DRIVER_MODE` выбирает полный профиль XYZ; смена `normal`/`quiet` сохраняет выбор и вызывает `FIRMWARE_RESTART`. Экструдер, токи и удержание не меняются.
- `TREED_UI_SET_DRIVER_FAN_MODE` принимает только `MODE=normal` и сохраняет полную мощность обдува. Пин и таймер принадлежат `controller_fan driver_fan`, критерий нагрузки задаёт `treed_driver_fan_mode`. Состояние обновляется следующим callback, обычно в пределах секунды. Повторное применение не сбрасывает защитный таймер и охлаждение.

Полный профиль `quiet` определён в `klipper-host/treed_driver_mode.py`:

| Параметр XYZ | `quiet` | `normal` |
| --- | --- | --- |
| Микрошаги | 128 | Из исходных конфигов |
| Интерполяция | Включена | Из исходных конфигов |
| Длительность импульса | 100 нс; both-edge выбирает Klipper при поддержке MCU | Из исходных конфигов |
| Режим TMC5160 | StealthChop без порога скорости | SpreadCycle |
| TOFF / HSTRT / HEND / TBL / TPFD | 3 / 5 / 2 / 2 / 4 | Из исходных конфигов |
| PWM OFS / GRAD / FREQ / REG / LIM | 30 / 0 / 0 / 4 / 12 | Из исходных конфигов |
| PWM AUTOSCALE / AUTOGRAD | Включены | Из исходных конфигов |
| Скорость / ускорение | 180 мм/с / 25 000 мм/с² | Из исходных конфигов |

`driver_mode.cfg` подключается первым в `printer.cfg`, до создания TMC и
шаговых осей. Модуль читает сохранённый режим и меняет только разобранный
конфиг в памяти. Поэтому расчёт шага Klipper, MRES и длительность импульса MCU
инициализируются согласованно. Позднее подключение отклоняется при загрузке.
`steppers.cfg`, `local_overrides.cfg` и SAVE_CONFIG-сегмент не переписываются;
возврат в `normal` заново читает их исходные значения. Фактические разобранные
параметры видны в `configfile.settings`; `configfile.config` отражает файлы на диске.

При загрузке `quiet` задаются 180 мм/с и 25 000 мм/с². Эти же потолки ограничивают
печать, travel, homing и сервисные перемещения через штатный toolhead. Более низкие
операционные ограничения сохраняются, включая отдельные лимиты Z.
Операционные настройки `M204`, `SET_VELOCITY_LIMIT` и сервисные вызовы
`set_max_velocities` в `quiet` применяются с указанными верхними границами.
Временные лимиты homing, очистки и восстановления возвращаются после операции.
Смена полного профиля перезапускает прошивку и хост: привязка осей и несохранённые
runtime-настройки сбрасываются, перед следующим движением требуется homing.
Команда сама homing или другие движения не выполняет. Повторный выбор уже
загруженного профиля не перезапускает систему и не повышает пониженные лимиты.

Сервисные перемещения проходят через `TREED_SERVICE_MOVE`: PARK — 100 мм/с,
RESUME_WIPE — 150 мм/с, START_WIPE — 300 мм/с и 12 500 мм/с², TRAVEL —
200 мм/с, Z_TRAVEL — 25 мм/с, CANCEL_Z — 5 мм/с. Возврат `RESUME` использует
значение штатного `[pause_resume] recover_velocity`. Скорость сервисного G1
учитывает M220 при исполнении, затем ограничивается действующим общим потолком
`toolhead.max_velocity`; меньший запрос не повышается. Для ручных движений UI
`FEEDRATE` сохраняется в мм/мин и передаётся как запрос мм/с. Штатный G1
сохраняет G-code координаты, offsets, mesh, границы и нативную защиту Z.
Измерительные скорости homing/probing/scan и экструзионные движения не меняются.
Вся подготовка и чистка сопла, включая ожидание нагрева и `M400`, выполняется
внутри guard. Ошибка возвращает сохранённые лимиты и G-code state без движения;
ошибка восстановления приводит к shutdown.
Контур использует `ToolHead.set_max_velocities` закреплённого Klipper ce7002bed;
при обновлении Klipper сверять этот API и потребителей M204/SET_VELOCITY_LIMIT.

XYZ разрешён только при готовом Klipper, вне печати, паузы, прочистки, ручной калибровки и сервисных операций. Допуск повторяется после `wait_moves` и сохранения нового выбора. До перезапуска MRES работающих драйверов не меняется. При отказе сохранения или запроса перезапуска восстанавливается предыдущий выбор вместе с остальными переменными; неподтверждённое восстановление переводит принтер в shutdown. При старте групповая запись полей TMC имеет откат; ошибка не позволяет подтвердить режим. Читаются GCONF и MRES из CHOPCONF, TPWMTHRS подтверждается записью без независимого readback.

Sensorless homing временно использует spreadCycle и восстанавливает рабочие поля. `mode` — выбранный профиль; `effective_modes` — текущие поля из кеша драйверов, включая временное переключение homing, не измерение шума или скорости.

Объекты Moonraker `treed_driver_mode` / `treed_driver_fan_mode` публикуют `contract_version: "1.0"`, `mode`, `state: ready|applying|fault`, `available_modes`, `needs_restart`, `message`. `treed_driver_mode.service_velocity_limit` сохраняет совместимое имя и публикует текущий глобальный `toolhead.max_velocity`; словарь `motion` публикует номиналы операций. Обдув дополнительно публикует `speed`, `active_speed`, `idle_speed`, `min_power=1`, `max_power=1`, `power_control=false`, `load_reason` и `load_delay` в секундах. `available_modes` обдува содержит только `normal`. Handshake `_TREED_UI_CONTRACT` остаётся версии 1.0; отдельные capability-флаги и наличие объектов/макросов разрешают UI показывать функции. UI не показывает регулировку мощности и недоступный тихий режим обдува.

Режимы сохраняются через `save_variables` в `~/printer_data/config/treed_variables.cfg`. Профиль выбирается до создания осей, а стартовое подтверждение TMC выполняется после `klippy:ready`. Loader сохраняет этот файл в режиме `preserve`, с явной ошибкой при неудаче копирования. `clean` сбрасывает локальные настройки. Сохранение использует штатную семантику `SAVE_VARIABLE`; отдельной атомарной записи диска extra не добавляет. При ошибке extra пытается повторно сохранить предыдущие переменные; постоянный отказ записи остаётся ошибкой, а не успешным откатом.

Переменная `driver_fan_mode` хранит строку `normal`. Старые значения `quiet` и
словари с `power` не применяются: при `klippy:ready` обдув устанавливается на 100%
с сообщением в статусе. Следующая команда `MODE=normal` сохраняет новое значение.

## Включение по нагрузке

Нагрев хотэнда или стола сам по себе не включает обдув. При включённых XYZ
обдув работает сразу в фазах `preparing`, `printing`, `paused`, `calibrating`
и `auto_remove`, при активном virtual SD и работе `treed_sgt_executor`.
Короткие ручные перемещения в `idle` не запускают вентилятор. Если XYZ остаются
включёнными, через `load_delay` (по умолчанию 30 с, допустимо 1..60 с) включается
обдув: неподвижное удержание тоже нагружает драйверы. Неизвестная фаза включает
обычную мощность без задержки. Таймер отсчитывается по монотонным часам,
состояние проверяется раз в секунду.

После нагрузки сохраняется охлаждение в течение `controller_fan.idle_timeout`
(по умолчанию 120 с) на `idle_speed`. Ручное движение после нагрузки не отменяет
охлаждение. Перезапуск очищает таймеры, включённые моторы снова проходят допуск.
Это правило по состояниям и времени, без измерения температуры драйверов.

## Мощность обдува

Подключённые вентиляторы вращаются только при 100% PWM. Активная скорость и
скорость охлаждения равны 1.0; между ними сохраняется прежний таймер охлаждения.
`MODE=quiet` и `POWER` отклоняются до сохранения. Значения `quiet_active_speed` и
`quiet_idle_speed` из старых `local_overrides.cfg` читаются для совместимости,
но не влияют на выход. Допуск к снижению мощности отсутствует. UI показывает
текущий заданный PWM и причину включения; тахометр для `driver_fan` не настроен.

## Применение и проверка

Успешная смена полного профиля автоматически вызывает `FIRMWARE_RESTART`.
До отключения статус содержит выбранный `mode`, `state=applying` и
`needs_restart=true`; это ожидание перезапуска, а не подтверждение применения.
HTTP accepted не равен готовому профилю. После загрузки сохранённый выбор
применяется автоматически; ошибка/таймаут не запускают повторный перезапуск.

Открытое окно сохраняется при очистке snapshot после shutdown. После ошибки UI
запрашивает состояние через HTTP; последнее подтверждённое требование перезапуска
остаётся в контексте окна. Применение требует свежего ready-состояния, а
`FIRMWARE_RESTART` — текущего системного допуска. Если после ошибки восстановлен
прежний выбор, повторную смену профиля оператор запрашивает отдельно.

Офлайн: `python -B tools/tests/test_driver_modes.py`. Проверяет групповую запись/откат, допуск, сохранение, профиль обдува и доставку; не подтверждает физический SPI, sensorless, шум, отсутствие пропусков шагов или тепловой запас. До аппаратной приёмки stealthChop нельзя считать проверенным рабочим профилем нагрузок этого принтера.
