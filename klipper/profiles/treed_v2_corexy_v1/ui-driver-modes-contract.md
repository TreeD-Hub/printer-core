# Режимы XYZ и обдува драйверов

Два независимых публичных макроса принимают только `MODE=quiet|normal`:

- `TREED_UI_SET_DRIVER_MODE` переключает TMC5160 XYZ между stealthChop и spreadCycle; экструдер, токи, microsteps и удержание не меняются.
- `TREED_UI_SET_DRIVER_FAN_MODE` меняет скорости штатного `controller_fan driver_fan`; автоматическое включение, `idle_timeout`, таймер и `last_on` сохраняются. Физический PWM обновляется следующим штатным callback, обычно в пределах секунды.

XYZ разрешён только при готовом Klipper, вне печати, паузы, прочистки, ручной калибровки и сервисных операций. Допуск повторяется после `wait_moves`. При частичной ошибке записи или сохранения режим откатывается для всех XYZ. Неподтверждённый откат переводит принтер в shutdown и требует явного `FIRMWARE_RESTART`. Читается GCONF; TPWMTHRS подтверждается записью, независимого readback этого регистра контракт не обещает.

Sensorless homing временно использует spreadCycle и восстанавливает рабочие поля. `mode` — выбранный профиль; `effective_modes` — текущие поля из кеша драйверов, включая временное переключение homing, не измерение шума или скорости.

Объекты Moonraker `treed_driver_mode` / `treed_driver_fan_mode` публикуют `contract_version: "1.0"`, `mode`, `state: ready|applying|fault`, `available_modes`, `needs_restart`, `message`. Обдув дополнительно публикует `speed`, `active_speed`, `idle_speed` (0..1). Handshake `_TREED_UI_CONTRACT` остаётся версии 1.0; отдельные capability-флаги и наличие объектов/макросов разрешают UI показывать функции.

Режимы сохраняются через `save_variables` в `~/printer_data/config/treed_variables.cfg` и восстанавливаются на `klippy:ready`. Loader сохраняет этот файл в режиме `preserve`, с явной ошибкой при неудаче копирования. `clean` сбрасывает локальные настройки. Сохранение использует штатную семантику `SAVE_VARIABLE`; отдельной атомарной записи диска extra не добавляет.

## Тихий обдув: аппаратный допуск

По умолчанию разрешён только `normal` (активная скорость 1.0, ожидание 0.5 из `service_fans.cfg`). После проверки старта вентилятора и нагрева драйверов под нагрузкой задайте в `local_overrides.cfg` секцию `[treed_driver_fan_mode]` с `quiet_active_speed`, `quiet_idle_speed` и `quiet_validated: True`. Готовых безопасных значений для этого оборудования пока нет.

Обе тихие скорости должны быть конечными, положительными, не ниже `off_below`; idle не выше active и обычного idle, active не выше обычного active. Неверная настройка останавливает загрузку конфига. Если сохранён quiet, но допуск удалён, загрузка возвращает обычный профиль и публикует причину.

## Применение и проверка

Обычная смена режима применяется без перезапуска. Первая установка extras и изменение конфигурации требуют перезапуска Klipper. UI показывает отдельное окно подтверждения; HTTP accepted не равен подтверждённому режиму. Ошибка/таймаут не запускают автоматический перезапуск; при `needs_restart` оператор может выполнить его в том же окне.

Открытое окно сохраняется при очистке snapshot после shutdown. После ошибки UI
запрашивает состояние через HTTP; последнее подтверждённое требование перезапуска
остаётся в контексте окна. Применение требует свежего ready-состояния, а
`FIRMWARE_RESTART` — текущего системного допуска. После перезапуска выбранный
режим не применяется автоматически: оператор повторно подтверждает применение,
если он отличается от восстановленной сохранённой настройки.

Офлайн: `python -B tools/tests/test_driver_modes.py`. Проверяет групповую запись/откат, допуск, сохранение, профиль обдува и доставку; не подтверждает физический SPI, sensorless, шум, отсутствие пропусков шагов или тепловой запас. До аппаратной приёмки stealthChop нельзя считать проверенным рабочим профилем нагрузок этого принтера.
