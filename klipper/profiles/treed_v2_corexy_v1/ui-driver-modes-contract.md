# Режимы XYZ и обдува драйверов

Два независимых публичных макроса управляют XYZ и обдувом:

- `TREED_UI_SET_DRIVER_MODE` переключает TMC5160 XYZ между stealthChop и spreadCycle; экструдер, токи, microsteps и удержание не меняются.
- `TREED_UI_SET_DRIVER_FAN_MODE` принимает только `MODE=normal` и сохраняет полную мощность обдува. Пин и таймер принадлежат `controller_fan driver_fan`, критерий нагрузки задаёт `treed_driver_fan_mode`. Состояние обновляется следующим callback, обычно в пределах секунды. Повторное применение не сбрасывает защитный таймер и охлаждение.

В `quiet` потолок скорости XYZ — **350 мм/с**, ускорения — **15 000 мм/с²**:
печать, travel, homing и сервисные перемещения через штатный toolhead.
Более низкие ограничения сохраняются, включая отдельные лимиты Z.
`M204`, `SET_VELOCITY_LIMIT` и сервисные вызовы `set_max_velocities` не могут
поднять потолок; скорость на углах также ограничена 350 мм/с.
В `normal` восстанавливаются runtime-лимиты перед первым входом в `quiet`;
повторный `quiet` не перезаписывает снимок. После перезапуска снимок берётся
из загруженной конфигурации. При ошибке переключения откатываются и лимиты.
Контур использует `ToolHead.set_max_velocities` закреплённого Klipper ce7002bed;
при обновлении Klipper сверять этот API и потребителей M204/SET_VELOCITY_LIMIT.

XYZ разрешён только при готовом Klipper, вне печати, паузы, прочистки, ручной калибровки и сервисных операций. Допуск повторяется после `wait_moves`. При частичной ошибке записи или сохранения режим откатывается для всех XYZ. Неподтверждённый откат переводит принтер в shutdown и требует явного `FIRMWARE_RESTART`. Читается GCONF; TPWMTHRS подтверждается записью, независимого readback этого регистра контракт не обещает.

Sensorless homing временно использует spreadCycle и восстанавливает рабочие поля. `mode` — выбранный профиль; `effective_modes` — текущие поля из кеша драйверов, включая временное переключение homing, не измерение шума или скорости.

Объекты Moonraker `treed_driver_mode` / `treed_driver_fan_mode` публикуют `contract_version: "1.0"`, `mode`, `state: ready|applying|fault`, `available_modes`, `needs_restart`, `message`. Обдув дополнительно публикует `speed`, `active_speed`, `idle_speed`, `min_power=1`, `max_power=1`, `power_control=false`, `load_reason` и `load_delay` в секундах. `available_modes` обдува содержит только `normal`. Handshake `_TREED_UI_CONTRACT` остаётся версии 1.0; отдельные capability-флаги и наличие объектов/макросов разрешают UI показывать функции. UI не показывает регулировку мощности и недоступный тихий режим обдува.

Режимы сохраняются через `save_variables` в `~/printer_data/config/treed_variables.cfg` и восстанавливаются на `klippy:ready`. Loader сохраняет этот файл в режиме `preserve`, с явной ошибкой при неудаче копирования. `clean` сбрасывает локальные настройки. Сохранение использует штатную семантику `SAVE_VARIABLE`; отдельной атомарной записи диска extra не добавляет.

Переменная `driver_fan_mode` хранит строку `normal`. Старые значения `quiet` и
словари с `power` не применяются: при `klippy:ready` обдув устанавливается на 100%
с сообщением в статусе. Следующая команда `MODE=normal` сохраняет новое значение.

## Включение по нагрузке

Нагрев хотэнда или стола сам по себе не включает обдув. При включённых XYZ
обдув работает сразу в фазах `preparing`, `printing`, `paused`, `calibrating`
и `auto_remove`, при активном virtual SD и работе `treed_sgt_executor`.
Короткие ручные перемещения в `idle` не запускают вентилятор. Если XYZ остаются
включёнными, через `load_delay` (по умолчанию 30 с, допустимо 1..60 с) включается
обдув: неподвижное удержание тоже нагружает драйверы. Неизвестная фаза включает
обычную мощность без задержки. Таймер отсчитывается по монотонным часам,
состояние проверяется раз в секунду.

После нагрузки сохраняется охлаждение в течение `controller_fan.idle_timeout`
(по умолчанию 120 с) на `idle_speed`. Ручное движение после нагрузки не отменяет
охлаждение. Перезапуск очищает таймеры, включённые моторы снова проходят допуск.
Это правило по состояниям и времени, без измерения температуры драйверов.

## Мощность обдува

Подключённые вентиляторы вращаются только при 100% PWM. Активная скорость и
скорость охлаждения равны 1.0; между ними сохраняется прежний таймер охлаждения.
`MODE=quiet` и `POWER` отклоняются до сохранения. Значения `quiet_active_speed` и
`quiet_idle_speed` из старых `local_overrides.cfg` читаются для совместимости,
но не влияют на выход. Допуск к снижению мощности отсутствует. UI показывает
текущий заданный PWM и причину включения; тахометр для `driver_fan` не настроен.

## Применение и проверка

Обычная смена режима применяется без перезапуска. Первая установка extras и изменение конфигурации требуют перезапуска Klipper. UI показывает отдельное окно подтверждения; HTTP accepted не равен подтверждённому режиму. Ошибка/таймаут не запускают автоматический перезапуск; при `needs_restart` оператор может выполнить его в том же окне.

Открытое окно сохраняется при очистке snapshot после shutdown. После ошибки UI
запрашивает состояние через HTTP; последнее подтверждённое требование перезапуска
остаётся в контексте окна. Применение требует свежего ready-состояния, а
`FIRMWARE_RESTART` — текущего системного допуска. После перезапуска выбранный
режим не применяется автоматически: оператор повторно подтверждает применение,
если он отличается от восстановленной сохранённой настройки.

Офлайн: `python -B tools/tests/test_driver_modes.py`. Проверяет групповую запись/откат, допуск, сохранение, профиль обдува и доставку; не подтверждает физический SPI, sensorless, шум, отсутствие пропусков шагов или тепловой запас. До аппаратной приёмки stealthChop нельзя считать проверенным рабочим профилем нагрузок этого принтера.
