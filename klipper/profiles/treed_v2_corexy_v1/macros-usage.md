# Методичка по макросам `treed_v2_corexy_v1`

Документ описывает фактические макросы активного Klipper-профиля TreeD V2 CoreXY V1: назначение, параметры, условия запуска и сохранение результата. Примеры с движением и нагревом — отдельные команды для соответствующего сценария, а не скрипт для последовательного выполнения.

Точка подключения — [`klipper/printer.cfg`](../../printer.cfg). Помимо [`macros.cfg`](macros.cfg) и его модулей `macros_*.cfg`, она подключает макросы из `probe_eddy_duo.cfg`, `service_fans.cfg`, `filament_sensor.cfg`, `gcode_features.cfg` и `driver_mode.cfg`. Последним подключается локальный `local_overrides.cfg`: настройки устройства могут отличаться от значений профиля ниже. Карта исходников приведена в разделе 17.

Быстрый поиск:

| Задача | Раздел |
| --- | --- |
| Запуск и завершение печати, параметры слайсера | 2, 13 |
| Поиск начала координат, пауза и отмена | 3, 4 |
| Загрузка, выгрузка, замена филамента и датчики | 5 |
| Настройки во время печати и ручное перемещение | 6 |
| Калибровка Eddy, стола и резонансов | 7, 8 |
| Парковка, продувочная линия и камера | 9, 10 |
| Сервис, сохранение и состояние для интерфейса | 11, 12, 16 |
| Подсветка и режимы драйверов | 15 |

Единицы: расстояния — мм, температуры — °C, ускорения — мм/с². `SPEED` обычно задаётся в мм/с; `FEEDRATE` команды ручного перемещения — в мм/мин. Имена команд и параметров сохраняются как в исходниках.

## 1. Как вызывать макросы

Режим XYZ задаётся командой `TREED_UI_SET_DRIVER_MODE MODE=quiet|normal`.
Обдув драйверов работает только на 100%; `TREED_UI_SET_DRIVER_FAN_MODE MODE=normal`
сбрасывает старую сохранённую настройку мощности.
[Допуск, сохранение и режимы драйверов](ui-driver-modes-contract.md).

Макросы вызываются из консоли Mainsail/Fluidd/KlipperScreen или через Moonraker `printer.gcode.script`.

Пример для консоли:

```gcode
START_PRINT BED_TEMP=60 EXTRUDER_TEMP=220
```

Пример для Moonraker:

```json
{"jsonrpc":"2.0","method":"printer.gcode.script","params":{"script":"PAUSE"},"id":1}
```

Правило эксплуатации:
- оператор и UI используют описанные здесь публичные команды с учётом допуска каждой команды;
- начальный `_` обозначает внутренние помощники или состояние; отсутствие `_` само по себе не делает команду публичной: например, `SET_Z_FROM_PROBE` — внутренний этап поиска Z;
- служебные команды `*_BASE`, `G28.1` и прямые вызовы внутренних этапов не заменяют публичную обёртку: так можно обойти её проверки и восстановление состояния;
- raw-команды Klipper для live-тюнинга (`M220`, `M221`, `SET_GCODE_OFFSET`, `SET_PRESSURE_ADVANCE` и т.п.) из TreeD Shell не слать напрямую, использовать `TREED_UI_*`.

## 2. Старт и завершение печати

### `START_PRINT`

Основная команда для start-gcode слайсера.

Минимальный вызов:

```gcode
START_PRINT BED_TEMP=60 EXTRUDER_TEMP=220
```

Этот минимальный вызов перед каждой печатью строит новую адаптивную Eddy mesh.

Параметры:

| Параметр | Значение по умолчанию | Что делает |
| --- | --- | --- |
| `BED_TEMP` | нет | Целевая температура стола. Обязательна, должна быть `> 0`. |
| `EXTRUDER_TEMP` | нет | Целевая температура сопла. Обязательна, не ниже `min_extrude_temp`. |
| `ADAPTIVE_MARGIN` | `5` | Отступ адаптивной сетки от объектов, мм; неотрицательное число. |
| `HOTEND_READY_MARGIN` | `3` | Допустимая разница до целевой температуры сопла перед продувочной линией, °C. Отрицательное значение приводится к нулю. |
| `TOTAL_LAYER` | ранее заданное число слоёв или `0` | Целое неотрицательное число. `0` очищает счётчик; порядок настройки слайсера — в разделе 13. |

Что делает `START_PRINT`:
1. До изменения состояния валидирует параметры и object-метаданные для нативной adaptive mesh.
2. Первой state-changing командой выполняет `BED_MESH_CLEAR`, затем сбрасывает G-code offsets.
3. Включает нагрев стола и preheat сопла, дожидается температуры стола.
4. Выполняет полный `G28` через sensorless X/Y и Eddy Z-home.
5. Строит новую mesh через Eddy в сервисных raw-координатах: `METHOD=rapid_scan ADAPTIVE=1` с отступом `ADAPTIVE_MARGIN`. Klipper сразу активирует результат.
6. Включает print-offset рабочей зоны, переезжает к началу purge-линии на Z не ниже 10 мм и устанавливает Z=0,4 мм для ожидания нагрева.
7. Догревает сопло, выполняет одну линию `_TREED_LINE_PURGE` на Z=0,4 мм у минимального Y, затем запускает runtime-сессию камеры.

Object labels в G-code и `enable_object_processing` в Moonraker обязательны для adaptive mesh: без polygon-метаданных `START_PRINT` завершится до очистки mesh и прогрева. Параметры `MESH`, `MESH_METHOD`, `MESH_PROFILE`, `MESH_MIN`/`MESH_MAX`, `SHAPER` и `SHAPER_ACCEL` отклоняются. Для сервисного сканирования используйте `TREED_BED_MESH_CALIBRATE_EDDY`. Высота ожидания сопла `heat_wait_height` задаётся отдельно от рабочего Z0.

### `END_PRINT`

Основная команда для end-gcode слайсера.

```gcode
END_PRINT
```

Автосъём по умолчанию выключен (`AUTO_REMOVE=0`). Чтобы включить его для конкретной печати, используйте в end-gcode:

```gcode
END_PRINT AUTO_REMOVE=1
```

Флаг действует только для текущего вызова. Допустимы только `0` и `1`; другое значение отклоняется до выполнения команд.

Что делает:
- сначала выключает нагреватели, обдув и останавливает камеру;
- при известной Z захватывает live Z-offset/babystep для Eddy autosave;
- отключает print-offset перед сервисной парковкой;
- при разрешённой экструзии делает retract; при достоверных X/Y/Z — Z-hop и парковку в raw-координатах;
- только при `AUTO_REMOVE=1` переходит в `auto_remove`, ждёт охлаждения стола до 40 °C, принудительно находит нижнюю опору через Z DIAG и выполняет пять циклов `Z-25/Z+25` на 50 мм/с;
- выполняет `M400`, `M84` и возвращает фазу `idle`; обычное завершение не ждёт охлаждения стола и не запускает нижнюю Z-парковку;
- применяет накопленную поправку Eddy Z, если она превышает порог сохранения; подробности — в разделе 7.

При неизвестных или выходящих за пределы координатах XY-парковка пропускается. При `AUTO_REMOVE=1` нижняя Z-парковка выполняется отдельным DIAG-контуром; ошибка DIAG или движения прекращает цикл до `M84`. `CANCEL_PRINT` автосъём не запускает.

## 3. Homing

### `G28`

Штатный `G28` переопределен TreeD-макросом.

```gcode
G28
G28 X
G28 Y
G28 Z
```

Поведение:
- X/Y идут через sensorless homing TMC5160;
- перед первым движением сбрасываются активная mesh и G-code offsets; `G28` оставляет сервисные raw-координаты;
- перед X/Y известная Z поднимается в пределах доступного хода; у верхней границы движение вниз запрещено;
- при неизвестной Z выполняется `TREED_Z_HOME_BOTTOM`: одна ограниченная sensorless-проба нижнего упора и безопасный отход; ошибка блокирует дальнейший homing;
- перед каждым X/Y завершается очередь движений и выдерживается не менее `2000 мс` без движения для сброса StallGuard; после срабатывания есть отход от упора на `10 мм`;
- Z всегда идет через Eddy-контур `_TREED_EDDY_HOME_Z`;
- отдельный `G28 Z` требует уже homed X/Y; неизвестная Z сначала получает нижнюю опору, затем рабочий Z0 ищет Eddy.

После потери координат выполните полный homing:

```gcode
G28
```

После успешного `G28` для парковки можно выполнить `G1 X10 Y235 F6000` в сервисных raw-координатах. Отдельный `G28 Z` использовать только после успешного `G28 X Y` или полного `G28`. При неизвестной Z и X/Y команда `G28 Z` не заменяет полный homing.

Нижняя опора запускается штатно при неизвестной Z; перед работой нужна
[аппаратная проверка](README.md#нижняя-опора-z). `TREED_Z_HOME_BOTTOM` можно вызвать
отдельно на свободном принтере; известная Z пропускается. Отход считается от
фактического DIAG, затем задаётся временная Z; перед печатью нужен Eddy Z0.
`TREED_Z_PARK_BOTTOM_MANUAL` на свободном принтере принудительно повторяет тот же
поиск через TMC5160/DIAG даже при известной Z и останавливается после безопасного
отхода `bottom_clearance_mm`; циклы автосъёма и `M84` не выполняются.
После Eddy доступный максимум равен меньшему из `position_max` и измеренной
высоты контакта минус запас `bottom_clearance_mm`. Он ограничивает движения
и публикуется через `toolhead.axis_maximum.z`; слайсер автоматически не меняется.
При ошибке Z остаётся неизвестной; при shutdown требуется `FIRMWARE_RESTART`.
Слепого fallback нет.

`TREED_Z_HOME_BOTTOM`, `TREED_Z_PARK_BOTTOM_MANUAL` и используемая завершением печати `TREED_Z_PARK_BOTTOM` зарегистрированы Python-расширением [`treed_z_recovery`](../../../klipper-host/treed_z_recovery.py), а не секциями `gcode_macro`. Диагностические `TREED_Z_RECOVERY_TEST`, `TREED_EDDY_ACCEPTANCE_HOME` и `TREED_EDDY_ACCEPTANCE_MESH` относятся к отдельной [приёмке Z/Eddy](../../../docs/z-eddy-acceptance.md); их не следует добавлять в стартовый G-code.

## 4. Пауза, продолжение и отмена

Общий допуск различает простой, подготовку печати, печать, паузу, калибровку и зарезервированный автосъём. UI-перемещения разрешены в простое, сервисная протяжка — в простое или на подтверждённой паузе. Во время подготовки, печати, калибровки и автосъёма ручная протяжка запрещена. После ошибки подготовки или калибровки `CANCEL_PRINT` сбрасывает закрытую фазу.

### `PAUSE`

```gcode
PAUSE
```

Что делает:
- сохраняет текущие цели хотэнда/стола и idle timeout;
- останавливает runtime-снимки камеры;
- делает retract `E-5`, Z-hop и парковку на механическом Y-min (штатно `X122,5 Y0`); print-offset на парковку не влияет;
- через 10 минут активной паузы снижает цель хотэнда до `140` °C, если она выше; при `RESUME` или отмене таймер сбрасывается;
- увеличивает idle timeout до `43200` секунд.

Повторный `PAUSE` при активной паузе не выполняет новую парковку, а пишет сообщение `PAUSE уже активна`.
Первый вызов требует активной печати и достоверных X/Y/Z в пределах осей до любых действий парковки.

### `RESUME`

```gcode
RESUME
```

Что делает:
- возвращает цели нагрева, действовавшие в момент `PAUSE`, включая изменение температуры во время печати;
- дожидается стола и хотэнда;
- делает purge `E50` и wipe в сервисной raw-зоне;
- восстанавливает idle timeout и print-offset;
- вызывает штатный `RESUME_BASE`;
- возвращает камеру, если она работала до паузы.

### `CANCEL_PRINT`

Кнопка отмены в UI использует штатный `/printer/print/cancel`. Host-расширение
`treed_print_cancel` сразу выключает нагрев и останавливает чтение SD-задачи,
прерывает `M109`/`M190`/`TEMPERATURE_WAIT` и отбрасывает оставшиеся команды
макроса. Затем выполняется cleanup ниже; задача получает статус `cancelled`.
Одиночный вызов из консоли Moonraker работает так же:

```gcode
CANCEL_PRINT
```

Что делает:
- сначала выключает нагреватели и вызывает штатный `CANCEL_PRINT_BASE`;
- при известной Z захватывает live Z-offset до его сброса; сохраняет уже захваченную поправку из `END_PRINT`, если она есть;
- отключает print-offset;
- сбрасывает состояние паузы;
- останавливает камеру;
- при достоверной Z и доступном ходе поднимает стол/голову; ошибка этого движения не отменяет уже выполненную остановку печати;
- после завершения движений переносит захваченную поправку больше `0,005` мм по модулю в калибровку Eddy через `Z_OFFSET_APPLY_PROBE` и `SAVE_CONFIG`; сохранение перезапускает Klipper.

Текущая команда движения/homing завершается штатно. Для немедленного отключения
движения используется аварийный стоп (`/printer/emergency_stop`), после которого
нужен отдельный перезапуск Klipper. Отмена не запускает автосъём.

### `CLEAR_PAUSE`

```gcode
CLEAR_PAUSE
```

Очищает состояние паузы и восстанавливает `idle_timeout`, если пауза была активна.
Печать эта команда не продолжает: для продолжения используется `RESUME`.

## 5. Филамент

Когда выбран режим `motion`, encoder сообщает об отсутствии движения, а switch всё ещё видит филамент, обычной паузе предшествует автоматическая прочистка: до пяти подач по `25` мм при `5` мм/с с повышением цели хотэнда и тока экструдера максимум на 20% в безопасных пределах. Перед каждой попыткой запоминается счётчик энкодера; печать возобновляется только при оценочном продвижении не менее `10` мм за эту попытку (`2,88` мм на счётный импульс). После пяти неудач исходный ток восстанавливается, хотэнд переводится на `140` °C, печать остаётся на паузе. `RESUME`, `CLEAR_PAUSE` и `CANCEL_PRINT` также прерывают цикл с восстановлением тока. Номинал энкодера и порог следует проверить на устройстве.

### `LOAD_FILAMENT`

```gcode
LOAD_FILAMENT
LOAD_FILAMENT LENGTH=120 SPEED=10
```

Параметры:
- `LENGTH` — длина протяжки в мм, по умолчанию `100`; знак нормализуется, направление определяется выбором `LOAD_FILAMENT` или `UNLOAD_FILAMENT`;
- `SPEED` — скорость в мм/с, по умолчанию `10`; значения ниже `0.1` приводятся к `0.1`.

Макрос требует прогретое сопло и допускается в простое или на подтверждённой паузе. Если хотэнд ниже `min_extrude_temp`, будет ошибка. Длинная протяжка разбивается на порции по `max_extrude_only_distance`. На время движения датчики наличия и движения филамента отключаются, затем восстанавливается выбранный режим `presence` или `motion`, а не произвольная прежняя комбинация включений. Есть отложенное восстановление датчиков на случай прерывания команды.

### `UNLOAD_FILAMENT`

```gcode
UNLOAD_FILAMENT
UNLOAD_FILAMENT LENGTH=120 SPEED=15
```

Параметры те же, что у `LOAD_FILAMENT`, но скорость по умолчанию — `15` мм/с. Направление движения отрицательное, но оператор передает положительную длину.
Во время активной печати команда запрещена; сценарий `M600` сначала ставит печать на паузу и только затем выгружает материал.

### `M600`: замена филамента

```gcode
M600 UNLOAD_TEMP=180 UNLOAD_LENGTH=50
```

Команда из слайсера вызывает `PAUSE REASON=filament_change`, дожидается парковки и выгружает филамент с текущей скоростью по умолчанию для `UNLOAD_FILAMENT` — `15` мм/с. `UNLOAD_LENGTH` — положительная длина в мм, по умолчанию `50`; `UNLOAD_TEMP` — температура для догрева перед выгрузкой, по умолчанию `180`, не ниже `min_extrude_temp`. Догрев выполняется только если экструзия ещё запрещена текущей температурой; команда не обещает охлаждение уже горячего сопла до `UNLOAD_TEMP`.

После выгрузки печать остаётся на паузе; через 10 минут паузы цель сопла снижается до `140` °C, если она выше. Для загрузки нового материала сначала прогрейте сопло до подходящей материалу температуры, выполните `LOAD_FILAMENT`, затем `RESUME`. Сам `LOAD_FILAMENT` нагрев не включает.

### Датчики филамента

```gcode
FILAMENT_SENSOR_STATUS
FILAMENT_SENSOR_SET_MODE MODE=motion
```

| Команда / режим | Действие |
| --- | --- |
| `FILAMENT_SENSOR_STATUS` | Выводит выбранный режим и признаки включения датчиков наличия и движения; не меняет их. |
| `FILAMENT_SENSOR_SET_MODE MODE=presence` | Оставляет включённым датчик наличия, отключает контроль движения. |
| `FILAMENT_SENSOR_SET_MODE MODE=motion` | Включает оба датчика; режим по умолчанию при отсутствии сохранённой настройки. |

Переключение запрещено при `print_stats.state=printing|paused`. Режим сохраняется в `save_variables.filament_sensor_mode` и восстанавливается после запуска Klipper. При отсутствии нужного датчика команда завершается ошибкой. Режима полного отключения в этом публичном макросе нет. Внутренние `_FILAMENT_SENSOR_*` временно управляют датчиками при протяжке; вызывать их вручную не требуется.

## 6. Live-тюнинг из UI

Эти команды являются публичным контрактом TreeD Shell. Они разрешены только во время `printing`/`paused` или когда `pause_resume.is_paused = true`.

| Команда | Пример | Диапазон |
| --- | --- | --- |
| `TREED_UI_SET_SPEED_FACTOR` | `TREED_UI_SET_SPEED_FACTOR PERCENT=120` | `10..300` % |
| `TREED_UI_SET_FLOW_FACTOR` | `TREED_UI_SET_FLOW_FACTOR PERCENT=97` | `50..150` % |
| `TREED_UI_SET_ACCEL` | `TREED_UI_SET_ACCEL ACCEL=12000` | `500..printer.max_accel` |
| `TREED_UI_SET_PRESSURE_ADVANCE` | `TREED_UI_SET_PRESSURE_ADVANCE ADVANCE=0.075` | `0..0.20` |
| `TREED_UI_SET_RETRACTION` | `TREED_UI_SET_RETRACTION RETRACT_LENGTH=0.9` | `0..5.0` мм |
| `TREED_UI_ADJUST_Z_OFFSET` | `TREED_UI_ADJUST_Z_OFFSET DELTA=0.02` | `-0.05..0.05` мм за команду, суммарно `-1.0..1.0` |

После успешной команды UI должен перечитать состояние через Moonraker objects, а не парсить текст `RESPOND`.
Минимальный набор объектов:
- `gcode_move`: `speed_factor`, `extrude_factor`, `homing_origin`;
- `toolhead`: `max_velocity`, `max_accel`;
- `extruder`: `temperature`, `target`, `pressure_advance`;
- `heater_bed`: `temperature`, `target`;
- `firmware_retraction`: `retract_length`;
- `gcode_macro _TREED_UI_TUNE_STATE`: `contract_version`, `applied_babystep`.

Для отображения Z-offset UI читает `gcode_move.homing_origin.z`; счётчик
`applied_babystep` обновляется вместе с ним командами профиля. Повторный homing
сбрасывает оба значения. `END_PRINT` и `CANCEL_PRINT` захватывают offset для
сохранения в Eddy probe, затем сбрасывают временные значения. Поправка больше
`0,005` мм по модулю сохраняется в калибровке probe, а не в live-счётчике UI.

### `TREED_UI_MOVE_AXIS`: ручное перемещение

```gcode
TREED_UI_MOVE_AXIS AXIS=X DISTANCE=10 FEEDRATE=3000
TREED_UI_MOVE_AXIS AXIS=Z DISTANCE=1 FEEDRATE=600
```

| Параметр | Значение и ограничение |
| --- | --- |
| `AXIS` | Обязателен: `X`, `Y` или `Z`; регистр нормализуется. |
| `DISTANCE` | Обязательное относительное перемещение, ненулевое, от `-50` до `50` мм. Знак задаёт направление по координатам оси. |
| `FEEDRATE` | Для X/Y: по умолчанию `3000`, допустимо `60..6000` мм/мин. Для Z: `600`, допустимо `60..1200` мм/мин. |

Команда разрешена только в простое, выбранная ось должна иметь достоверную привязку. Макрос проверяет конечную координату по настройкам оси; дополнительные ограничения движения, включая измеренный предел Z, остаются за Klipper и host-расширениями. Макрос временно включает относительные координаты и восстанавливает режим G-code без обратного перемещения. Во время печати или паузы это не команда ручной коррекции Z: для неё используется `TREED_UI_ADJUST_Z_OFFSET`.

## 7. Bed mesh и Eddy

### `TREED_BED_MESH_CALIBRATE_EDDY`

Публичная Eddy-aware обертка для построения mesh. Штатный `BED_MESH_CALIBRATE` тоже переопределен и маршрутизируется сюда.

Примеры:

```gcode
TREED_BED_MESH_CALIBRATE_EDDY PROFILE=default METHOD=scan
TREED_BED_MESH_CALIBRATE_EDDY PROFILE=treed_adaptive METHOD=scan ADAPTIVE=1 ADAPTIVE_MARGIN=5
TREED_BED_MESH_CALIBRATE_EDDY PROFILE=eddy_test METHOD=rapid_scan MESH_MIN=80,80 MESH_MAX=165,165 PROBE_COUNT=3,3 SCAN_SPEED=60
BED_MESH_CALIBRATE PROFILE=default METHOD=automatic
```

Макрос:
- использует отдельную безопасную Eddy scan area `X10..235 / Y10..210`;
- принимает `MESH_MIN`/`MESH_MAX` внутри этой области и отвергает некорректные координаты до движения;
- не расширяет область движения и печати `X0..245 / Y0..245`;
- чистит старую mesh-трансформацию;
- доhomит только неизвестные оси;
- временно отключает print-offset, если он был включен;
- передает эффективные `MESH_MIN`/`MESH_MAX` в базовый Klipper `BED_MESH_CALIBRATE_BASE`;
- принимает `SCAN_SPEED` только для `METHOD=rapid_scan`; для остальных методов скорость XY берется из `[bed_mesh] speed`.

`TREED_EDDY_BED_MESH_CALIBRATE` также передаёт необязательные `MESH_MIN`/`MESH_MAX` в эту обертку. При `y_offset: -30` штатная область датчика `Y10..210` соответствует перемещению головы `Y40..240`.

Это Eddy service mesh в safe scan area, а не скан всей области печати. Scan area меньше стола, потому что sensing point датчика смещен относительно сопла и не может физически покрыть всю заднюю часть `245x245`.

### `TREED_Z_PARK_ZERO_EDDY`

```gcode
TREED_Z_PARK_ZERO_EDDY
```

Ручной рабочий поиск Z0 через Eddy. Использует тот же контур, что `G28 Z`; требует заранее привязанных X/Y и известной Z.

### `PROBE_EDDY_CURRENT_CALIBRATE_AUTO`

Запускайте только после того, как Z достоверно привязана. При неизвестной Z
макрос должен остановиться; для первого запуска нужен отдельный проверенный
сервисный порядок. Полная последовательность: [`docs/eddy-calibration.md`](../../../docs/eddy-calibration.md).

```gcode
PROBE_EDDY_CURRENT_CALIBRATE_AUTO CHIP=btt_eddy
```

Первичная калибровка Eddy с учетом безопасной scan area и runtime `[force_move]`. Макрос сам требует предварительно достоверной Z-позиции и при неизвестной Z прерывается до своего `G28 X Y`. После проверки Z ставит Eddy в центр `X10..235 / Y10..210` и запускает штатный `PROBE_EDDY_CURRENT_CALIBRATE`.

После интерактивной калибровки сохранять через:

```gcode
TREED_SAVE_CONFIG
```

### `TREED_SCREWS_TILT_CALIBRATE`

```gcode
TREED_SCREWS_TILT_CALIBRATE
```

Выравнивание четырех винтов стола через Eddy. Макрос чистит mesh, выполняет `G28`, ждет 1 секунду и запускает `SCREWS_TILT_CALCULATE`.

### Пошаговые команды калибровки Eddy для интерфейса

Это команды отдельных этапов, а не один автоматический сценарий. Оператор выполняет бумажную пробу, прогрев датчика и регулировку винтов по [инструкции Eddy](../../../docs/eddy-calibration.md). Перед первичной калибровкой высоты нужна достоверная Z; этот этап не восстанавливает её самостоятельно.

| Команда | Действие и следующий шаг |
| --- | --- |
| `TREED_EDDY_CALIBRATE_DRIVE_CURRENT` | Выполняет `LDC_CALIBRATE_DRIVE_CURRENT CHIP=btt_eddy`, сохраняет конфигурацию и перезапускает Klipper. Дождитесь готовности перед следующим этапом. |
| `TREED_EDDY_PRIMARY_HEIGHT_START` | Запускает `PROBE_EDDY_CURRENT_CALIBRATE_AUTO CHIP=btt_eddy`; дальше выполняется интерактивная бумажная проба. |
| `TREED_EDDY_PRIMARY_ACCEPT_SAVE` | Вызывает `ACCEPT`, отмечает первичную калибровку выполненной, сохраняет конфигурацию с перезапуском. Вызывать только после настройки высоты в активной процедуре. |
| `TREED_EDDY_TEMPERATURE_START` | Выполняет `G28`, задаёт тайм-аут простоя `36000` с и запускает `TEMPERATURE_PROBE_CALIBRATE PROBE=btt_eddy TARGET=56 STEP=4`. Значения относятся к температуре датчика; отдельной команды нагрева стола здесь нет. |
| `TREED_EDDY_TEMPERATURE_ACCEPT_SAVE` | Принимает текущую интерактивную калибровку через `ACCEPT`, сохраняет результат и перезапускает Klipper. |
| `TREED_EDDY_CHECK_Z0` | Выполняет `G28` и повторный поиск рабочего нуля через `TREED_Z_PARK_ZERO_EDDY`, затем отмечает этап завершённым. Оператор проверяет физический результат отдельно. |
| `TREED_EDDY_SCREWS_TILT_START` | Запускает измерение четырёх винтов через `TREED_SCREWS_TILT_CALIBRATE`; регулировка остаётся за оператором. |
| `TREED_EDDY_SCREWS_TILT_DONE` | Только записывает подтверждение завершения регулировки. Нового измерения не выполняет. |
| `TREED_EDDY_BED_MESH_CALIBRATE` | Строит `PROFILE=default METHOD=scan`, передаёт необязательные `MESH_MIN`/`MESH_MAX`, сохраняет конфигурацию и перезапускает Klipper. Остальные параметры сервисной обёртки этой командой не передаются. |

Стартовые этапы отклоняются при активной печати или паузе. Команды `*_ACCEPT_SAVE` и `*_DONE` не заменяют проверку правильного этапа оператором: сохранённый признак завершения не является независимым подтверждением качества измерений.

Состояние хранится в `save_variables` под именами `treed_eddy_*`: активный этап, подсказка оператору и признаки завершения. `_TREED_EDDY_CALIBRATION_STATE` описывает этот контракт; для актуальных сохранённых значений UI читает объект `save_variables`.

### Автосохранение поправки Eddy Z

Диагностическая команда:

```gcode
TREED_EDDY_Z_OFFSET_AUTOSAVE_STATUS
```

Команда выводит `pending_z` и `has_pending`, ничего не сохраняет. В текущем профиле отдельного публичного выключателя автосохранения нет. `END_PRINT` при известной Z захватывает `gcode_move.homing_origin.z`; поправка становится ожидающей сохранения, если её модуль больше `0.005` мм (`threshold` в `_TREED_EDDY_Z_OFFSET_AUTOSAVE_STATE`).

При наличии ожидающей поправки завершающий этап вызывает `Z_OFFSET_APPLY_PROBE`, сбрасывает временную поправку UI и выполняет `SAVE_CONFIG`. Это меняет сохранённую калибровку Eddy и вызывает перезапуск Klipper; при нулевой или слишком маленькой поправке сохранения нет. `CANCEL_PRINT` не запускает этот сценарий. `pending_z` — оперативное состояние макроса, а не журнал, устойчивый к потере питания.

## 8. Input shaper

### `TREED_SHAPER_CALIBRATE_FULL`

Полная ручная калибровка input shaper с сохранением результата.

```gcode
TREED_SHAPER_CALIBRATE_FULL ACCEL=25000
```

По умолчанию:
- делает `G28`;
- запускает full sweep;
- вызывает `TREED_SAVE_CONFIG`, если `SAVE=1`.

Вариант без сохранения:

```gcode
TREED_SHAPER_CALIBRATE_FULL ACCEL=25000 SAVE=0
```

### `TREED_SHAPER_CALIBRATE_LIGHT`

Легкая калибровка вокруг уже сохраненных `shaper_freq_x/y`, без рестарта.

```gcode
TREED_SHAPER_CALIBRATE_LIGHT ACCEL=12000
```

Требует, чтобы full-калибровка уже была сохранена. Вручную запрещена во время активной печати и паузы.

### `TREED_SHAPER_CALIBRATE`

Базовая команда с явным режимом:

```gcode
TREED_SHAPER_CALIBRATE MODE=light ACCEL=12000 SAVE=0 HOME=1
TREED_SHAPER_CALIBRATE MODE=full ACCEL=25000 SAVE=1 HOME=1
```

Калибровка допускается только в простое и запускается отдельно от `START_PRINT`.

Основные параметры базовой команды:

| Параметр | Значение по умолчанию / смысл |
| --- | --- |
| `MODE` | `light`; допустимы `full` и `light`. |
| `HOME` | `1`: выполнить `G28`; при `0` X/Y/Z должны быть уже привязаны. |
| `SAVE` | `1` для `full`, `0` для `light`; `1` сохраняет результат с перезапуском Klipper. |
| `ACCEL` | `auto`: `25000` для `full`, текущий `toolhead.max_accel` для `light`; явное значение должно быть положительным. |
| `FREQ_START`, `FREQ_END` | Для полной калибровки: `5` и `133` Гц. Начало не ниже `1`, конец больше начала. |
| `HZ_PER_SEC` | Скорость прохода по частотам, по умолчанию `2` Гц/с; должна быть положительной, значения выше `2` ограничиваются до `2`. |
| `WINDOW`, `FREQ_MIN`, `FREQ_MAX` | Для лёгкой калибровки: окно `24` Гц вокруг сохранённой частоты каждой оси, с границами `5..133` Гц. |
| `LIGHT_HZ_PER_SEC` | Скорость лёгкого прохода; по умолчанию `HZ_PER_SEC` или `2`, с тем же ограничением. |
| `ACCEL_PER_HZ` | По умолчанию `0`: вычисляется как `ACCEL / верхняя частота`. Положительное значение задаёт коэффициент явно; отрицательное запрещено. |

Короткие команды `TREED_SHAPER_CALIBRATE_FULL` и `TREED_SHAPER_CALIBRATE_LIGHT` передают только `ACCEL`, `SAVE`, `HOME`. Для настройки частот используйте базовую `TREED_SHAPER_CALIBRATE`. Параметры выше описывают программный контракт, а не аппаратное подтверждение допустимых нагрузок.

## 9. Фиксированные park/purge

Эти helper-ы скрыты от Fluidd префиксом `_` и вручную обычно не вызываются: `START_PRINT` вызывает их сам после homing и mesh, при включённом print-offset.

### `_TREED_SMART_PARK`

```gcode
_TREED_SMART_PARK
```

Переезжает к началу линии у минимального Y в print-координатах на Z не ниже `park_height`, затем устанавливает `heat_wait_height` для ожидания нагрева с зазором, без контакта сопла со столом. Требует homed X/Y/Z и включённый print-offset; при нарушении контракта завершится ошибкой до движения.

### `_TREED_LINE_PURGE`

```gcode
_TREED_LINE_PURGE
```

Проводит одну прямую вдоль X длиной в половину ширины print-area. Начало задано отступом `x_inset` от X-min, положение Y — отступом `y_inset` от Y-min. При штатной геометрии 245×245 мм это `X10 → X132,5`, `Y5`, `Z0,4`, подача `E30`, скорость `F400` (мм/мин). Передняя полоса линии должна оставаться свободной от модели. Требует homed X/Y/Z, включённый print-offset и сопло, готовое к экструзии.

Из начальной точки макрос переходит прямо на высоту линии; из другой точки сначала выполняет XY-переезд на Z не ниже `park_height`. После линии поднимается на `park_height`. PA сохраняет текущее значение, в том числе нулевое; переключения PA и firmware retract нет.

Параметры находятся в `_TREED_START_PURGE_CFG`:

| Параметры | Значения по умолчанию |
| --- | --- |
| `park_height` / `heat_wait_height` / `purge_height` | 10,0 / 0,4 / 0,4 мм |
| `x_inset` / `y_inset` | 10,0 / 5,0 мм |
| `prime_amount` | 30,0 мм филамента на всю линию |
| `purge_speed` | 400,0 мм/мин |

Высота ожидания должна быть положительной, выше нижнего предела Z и не выше высоты purge. Высота перемещения должна быть выше высоты purge и не превышать верхний предел Z. Линия с запасом по расчётной ширине должна помещаться в print-area; расход не должен превышать `extruder.max_extrude_cross_section`. Неверные настройки отклоняются до движения. Расчёт ширины предполагает заполненную дорожку; фактическую ширину и подачу нужно проверить на принтере. Если в `local_overrides.cfg` заданы старые параметры purge, сверить прежде всего высоты и `prime_amount`; параметры двух линий больше не используются.

На время purge коэффициенты скорости и подачи устанавливаются в 100%. Исходные коэффициенты и G-code состояние восстанавливаются без движения после purge и при `CANCEL_PRINT`. Если purge прерван ошибкой команды, перед повторным вызовом нужен `CANCEL_PRINT` для восстановления состояния.

## 10. Камера

Камера управляется автоматически:
- `START_PRINT` вызывает `_TREED_CAM_START`;
- `END_PRINT` и `CANCEL_PRINT` вызывают `_TREED_CAM_STOP`;
- `PAUSE` останавливает тикер снимков;
- `RESUME` возвращает тикер, если камера работала до паузы.

Runtime-снимки завязаны на Moonraker shell-command `treed_cam_session_start`, `treed_cam_snapshot`, `treed_cam_session_stop`.

## 11. Сервисные команды

### `TREED_SAVE_CONFIG`

```gcode
TREED_SAVE_CONFIG
```

Обёртка `SAVE_CONFIG`, запрещённая во время печати и паузы. Сохраняет накопленные калибровочные изменения в конфигурации и перезапускает Klipper. После вызова дождитесь состояния `ready`; прежняя привязка осей не сохраняется. Это не сохранение всех оперативных значений UI: например, скорость и поток не становятся настройками профиля от одного вызова этой команды.

### `TREED_XY_MOTION_TEST`

```gcode
TREED_XY_MOTION_TEST
TREED_XY_MOTION_TEST SPEED=200 ACCEL=5000 ITER=2 Z=20 END_Z=100
```

Сервисный stress-test XY после полного homing.

Основные параметры:
- `SPEED` — скорость XY в мм/с, по умолчанию `200`;
- `ACCEL` — ускорение, по умолчанию `5000`;
- `ITER` — число повторов, по умолчанию `2`;
- `MARGIN` — отступ от краев, по умолчанию `15`;
- `Z` — безопасная высота перед XY-тестом, по умолчанию `20`;
- `END_Z` — финальная Z-позиция после теста, по умолчанию `100`;
- `SCV` — square corner velocity, по умолчанию текущее значение;
- `ZIGZAG_STEPS`, `CIRCLE_RADIUS`, `SMALL_STEP`, `SMALL_REPEATS` — форма тестовой траектории.

Запрещен во время печати и паузы.

### `TREED_MOTION_LIMITS_DEFAULT`

```gcode
TREED_MOTION_LIMITS_DEFAULT
```

Восстанавливает `VELOCITY`, `ACCEL` и `SQUARE_CORNER_VELOCITY` из секции `[printer]`.

### Совместимость со штатным G-code

`SET_IDLE_TIMEOUT TIMEOUT=<секунды>` переопределён для учёта текущего тайм-аута в `_TREED_IDLE_TIMEOUT_STATE` и передачи команды штатному `SET_IDLE_TIMEOUT_BASE`. Пауза использует этот учёт, чтобы вернуть прежнее значение при продолжении. Изменение действует в текущей сессии; файл конфигурации команда не переписывает.

`M486` из [`gcode_features.cfg`](gcode_features.cfg) переводит команды исключения объектов в `EXCLUDE_OBJECT*`:

| Параметр | Действие |
| --- | --- |
| `T<число>` | Сбросить реестр и определить указанное количество объектов с числовыми именами. |
| `C` | Исключить текущий объект. |
| `P<номер>` | Исключить объект по номеру. |
| `S<номер>` / `S-1` | Начать объект / завершить текущий объект. |
| `U<номер>` | Снять исключение указанного объекта. |

Пример: `M486 P1`. Созданные через `M486 T...` записи не содержат полигонов, поэтому сами по себе не удовлетворяют требованию адаптивной сетки `START_PRINT`. Команды `G2/G3`, `G10/G11`, `SET_PRINT_STATS_INFO`, `SAVE_VARIABLE` — штатные возможности Klipper, не отдельные TreeD-макросы.

## 12. Capability state для TreeD Shell

Эти макросы не выполняют действие, а публикуют state surface для UI:

```gcode
_TREED_SYSTEM_POWER
_TREED_SERVICE_COMMANDS
```

Поля:
- `_TREED_SYSTEM_POWER.enabled = 1` — UI может показывать reboot/shutdown host;
- `_TREED_SERVICE_COMMANDS.enabled = 1` — UI может показывать restart Klipper/Firmware/Moonraker.

Сами reboot/shutdown/restart должны выполняться штатными Moonraker endpoints и только после подтверждения в UI.

```gcode
START_PRINT BED_TEMP=[first_layer_bed_temperature] EXTRUDER_TEMP=[first_layer_temperature] TOTAL_LAYER=[total_layer_count]
; печатный G-code
END_PRINT
```

### Текущий слой в OrcaSlicer и TreeD UI

В настройках принтера OrcaSlicer → Machine G-code:

- В существующую строку `START_PRINT` добавить `TOTAL_LAYER=[total_layer_count]`,
  сохранив остальные параметры и object labels для adaptive mesh.
- В `Layer change G-code` (после смены слоя) добавить:

```gcode
SET_PRINT_STATS_INFO CURRENT_LAYER={layer_num}
```

В актуальном OrcaSlicer `layer_num` в этом поле начинается с `1`:
[переменные слайсера](https://github.com/OrcaSlicer/OrcaSlicer/wiki/built_in_placeholders_variables).
Перед печатью проверить экспорт: первая команда должна содержать `CURRENT_LAYER=1`,
последняя — номер последнего слоя. Для старой версии, экспортирующей первый слой
как `0`, использовать `{layer_num + 1}`. Не добавлять `+1` к уже единичной нумерации.
При печати объектов по очереди сверить экспортированный счётчик со всей задачей.

`START_PRINT` проверяет `TOTAL_LAYER` до нагрева и движения и публикует `0 / N`
на подготовке. Параметр необязателен: без него используется ранее переданный
`SET_PRINT_STATS_INFO TOTAL_LAYER=...`; если числа слоёв нет, Klipper публикует
неизвестные значения. `TOTAL_LAYER=0` явно очищает оба поля.
Пауза и возобновление сохраняют счётчик; новая SD-задача сбрасывает предыдущий.
Источник UI — `print_stats.info.current_layer` и `print_stats.info.total_layer`
через Moonraker, согласно [контракту Klipper](https://www.klipper3d.org/Status_Reference.html#print_stats).
Высота Z и процент выполнения не используются для вычисления слоя.

Уже нарезанные файлы без этих команд нужно перенарезать. Комментарии
`;LAYER_CHANGE` сами по себе не обновляют `print_stats`. Если в файле есть только
`TOTAL_LAYER`, значение останется `0 / N` и не будет означать текущий слой модели.
Изменения профиля и UI нужно доставить штатным обновлением; настройка слайсера
не обновляет конфиги устройства автоматически.

### Ручная загрузка филамента

```gcode
M104 S220
M109 S220
LOAD_FILAMENT LENGTH=120 SPEED=10
```

### Ручная выгрузка филамента

```gcode
M104 S220
M109 S220
UNLOAD_FILAMENT LENGTH=120 SPEED=15
```

### Команды калибровки Eddy после проверки достоверной Z

```gcode
LDC_CALIBRATE_DRIVE_CURRENT CHIP=btt_eddy
TREED_SAVE_CONFIG
PROBE_EDDY_CURRENT_CALIBRATE_AUTO CHIP=btt_eddy

```

Этот короткий список не заменяет полный порядок: перед каждым запуском AUTO
сначала восстановите достоверную Z-позицию и следуйте
[`docs/eddy-calibration.md`](../../../docs/eddy-calibration.md). Интерактивные
шаги `ACCEPT`/paper test выполняются по подсказкам Klipper.


## 14. Что не делать

- Не вызывать внутренние `_TREED_*` helper-макросы вручную, кроме явно описанных сервисных команд.
- Не слать из TreeD Shell raw live-tune команды вместо `TREED_UI_*`.
- Не запускать `TREED_SAVE_CONFIG`, shaper-калибровку или XY stress-test во время печати/паузы.
- Не запускать `G28 Z`, пока X/Y не homed.
- Не запускать `START_PRINT`, если в G-code нет object labels с polygon-координатами.
- Учитывать, что `END_PRINT` с накопленной поправкой Z может изменить сохранённую калибровку Eddy и перезапустить Klipper.

## 15. Подсветка и режимы драйверов

### Подсветка камеры печати

```gcode
LIGHT_ON
```

`LIGHT_ON` включает выход `chamber_light`, `LIGHT_OFF` выключает его. Эти команды не сохраняют предпочтение на следующий запуск.

```gcode
TREED_LIGHT_SETTINGS STARTUP=0 PRINT_START=1
```

`TREED_LIGHT_SETTINGS` принимает `STARTUP=0|1` и/или `PRINT_START=0|1`: включать свет после запуска Klipper и при старте печати. Значения по умолчанию при отсутствии сохранённых настроек — `0` и `1`. Другие имена параметров и значения отклоняются; вызов без параметров ничего не меняет.

Настройки сохраняются как `save_variables.light_on_startup` и `light_on_print_start`. Команда меняет предпочтение, а не текущее состояние света. Значение `0` отключает автоматическое включение: уже горящий свет этот обработчик не выключает. Завершение или отмена печати также не являются автоматической командой `LIGHT_OFF`.

### Двигатели XYZ и обдув драйверов

| Команда | Назначение |
| --- | --- |
| `TREED_UI_SET_DRIVER_MODE MODE=normal` | Обычный режим TMC5160 XYZ — spreadCycle. |
| `TREED_UI_SET_DRIVER_MODE MODE=quiet` | Тихий режим XYZ — stealthChop; экструдер не переключается. |
| `TREED_UI_SET_DRIVER_FAN_MODE MODE=normal` | Обдув драйверов на 100% при нагрузке и последующем охлаждении. |

Публичные макросы передают параметры host-расширениям `treed_driver_mode` и `treed_driver_fan_mode`; они выполняют проверки, применение и сохранение режима. Для XYZ нужен готовый принтер вне печати, паузы, прочистки и сервисных операций. Режимы сохраняются через `save_variables`; перезапуск для обычного переключения не нужен.

Для этого подключения `MODE=quiet` и `POWER` отклоняются: при меньшем PWM вентиляторы не вращаются. UI получает единственный доступный режим и признак отсутствия регулировки из состояния устройства. Полный контракт ошибок, отката и сохранения: [режимы XYZ и обдува](ui-driver-modes-contract.md).

## 16. Что сохраняется между запусками

| Данные | Где живут / как сохраняются |
| --- | --- |
| Настройки света, режим датчиков, режимы драйверов и этапы Eddy | `save_variables`, штатно `~/printer_data/config/treed_variables.cfg`; сохраняются соответствующей командой через `SAVE_VARIABLE`. |
| Калибровки Eddy, сетка стола и input shaper | Конфигурация Klipper через `SAVE_CONFIG` / `TREED_SAVE_CONFIG`; сохранение сопровождается перезапуском. У конкретного сценария должен быть этап сохранения. |
| Фаза операции, состояние паузы, камера, временная поправка Z и ожидающая поправка Eddy | Оперативное состояние макросов и расширений; не использовать как журнал восстановления после отключения питания. |
| Скорость, поток, ускорение, Pressure Advance и ретракт из UI | Текущие параметры Klipper. Эти команды сами не записывают постоянный профиль; дальнейшие макросы также могут их менять. |

Исходники профиля и локальные настройки имеют разных владельцев: порядок доставки и сохранения описан в [контракте конфигурации](../../../docs/config-ownership.md). Факт успешной команды не означает, что конфиги из репозитория уже установлены на конкретном принтере.
