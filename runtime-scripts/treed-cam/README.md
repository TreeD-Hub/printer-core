# Скрипты камеры TreeD

Снимки и сессии печати для интеграции Klipper/Moonraker, а также отдельный
диагностический клиент MJPEG. Ошибка снимка не прерывает печать.

## Скрипты и поведение

- `cam_env.sh`
  - единый helper для runtime-переменных камеры;
  - читает optional override-файл `${PI_HOME}/treed/cam/config/runtime.env`;
  - возвращает snapshot endpoint через `TREED_CAM_SNAPSHOT_URL` (или дефолт).
- `session_start.sh`
  - создает уникальный каталог новой сессии в `${PI_HOME}/treed/cam/prints`, включая повтор того же файла в ту же секунду;
  - записывает путь активной сессии в marker-файл `/tmp/treed_cam_session_dir`;
  - инвалидирует прежний `.latest_session`, публикует `session.json` с полным именем задания и новый указатель через `session_metadata.py`;
  - делает стартовый снимок в best-effort режиме;
  - при сбое snapshot пишет ограниченное предупреждение в stderr (throttled).
- `snapshot.sh`
  - проверяет наличие marker-файла сессии;
  - при активной сессии сохраняет очередной снимок в каталог сессии;
  - при отсутствии сессии/ошибке камеры завершает работу безопасно (`exit 0`) с throttled warning.
- `session_stop.sh`
  - закрывает `session.json` активного каталога и удаляет `/tmp/treed_cam_session_dir`;
  - идемпотентен (повторный вызов безопасен).
- `session_metadata.py`
  - сохраняет `sessionId`, исходный полный `filename`, токен печатной сессии, `startedAt`, `finishedAt` и `closed`;
  - использует Python 3 без дополнительных зависимостей, атомарную замену JSON и только прямой каталог сессии;
  - принимает токен только от production-макросов; ручной запуск без токена оставляет снимки, но не публикует сессию для оценки;
  - старый отложенный stop с несовпадающим токеном не закрывает новую сессию и не удаляет её marker;
  - сбой метаданных пишет предупреждение; снимки продолжают сохраняться, оценка недоступна.
- `stream_detect.py`
  - камера MJPEG → приватный локальный Unix socket сервиса зрения; использует стандартную библиотеку Python;
  - сохраняет JPEG в активную сессию и передаёт в Moonraker только точные `session_id/frame_id/captured_at` вместе с provenance ответа worker;
  - при сетевой ошибке, недоступности модели, смене сессии или устаревшем кадре сбрасывает серию через локальный detection endpoint;
  - хранит только кадры с собственным `detect_<uuid>_*.jpg` именем, с общим пределом 128 MiB; snapshots пользователя не затрагивает;
  - анализирует кадры только локальной службой и сам не отправляет G-code.

## Локальная оценка кадров

`stream_detect.py --react --fps 0.2 --vision-socket ${PI_HOME}/treed/vision/run/vision.sock` запускается unit-файлом `treed-detection.service`. MJPEG по умолчанию читается с loopback ustreamer; IPC v1 — newline JSON, кадр до 8 MiB, полный запрос до 12 MiB, ответ до 64 KiB. `TREED_VISION_SOCKET` задаёт путь сокета, `TREED_CAM_STREAM_URL` — локальный MJPEG, `TREED_DETECT_MOONRAKER_URL` — локальный Moonraker (default `http://127.0.0.1:7125`), `MOONRAKER_API_KEY` — optional локальную авторизацию.

Adapter публикует результат на `/server/treed/detection/result` с точными полями сессии/кадра и worker generation; unavailable и ошибки вызывают `POST /server/treed/detection/reset`. Серия обнуляется также при смене сессии и потере свежести кадра свыше 6 секунд. Период кадров ограничен минимумом 5 секунд штатной настройкой службы; кадр, снятый во время прогрева, отбрасывается. Adapter не выполняет проверку стола; её делает локальный клиент Moonraker в пределах собственного оставшегося deadline.

Локальные настройки можно хранить в `${PI_HOME}/treed/cam/config/runtime.env`; loader сохраняет этот файл при обновлении. Проверка: `python -B tools/tests/test_stream_detect.py`.

## Реакция на подтверждённые кадры

Режим `--react` публикует на локальный endpoint `/server/treed/detection/result` verdict, score, `session_id`, `frame_id`, `captured_at`, `worker_generation` и `model_version`. Moonraker сверяет активную сессию, JPEG, временную метку, порядок кадров и происхождение worker-а. Три положительных результата одной модели и одного поколения в пределах 12 секунд при промежутке не более 6 секунд запрашивают `PAUSE`; клиент не подтверждает инцидент и не отправляет G-code. Нормальный, неизвестный или недоступный результат, смена сессии, потеря свежести кадра либо ошибка IPC сбрасывают серию через `/server/treed/detection/reset`.

Порог spaghetti закреплён в локальном model manifest и равен **0,3**. Системный adapter захватывает кадр каждые 5 секунд; в последовательность входят только свежие кадры с максимальным возрастом 6 секунд. Оценка имеет предел 6 секунд, а отсутствие доступного результата более 30 секунд отражается в статусе и предупреждении `treed_detection`.

Loader создаёт `treed-vision.service` и `treed-detection.service`. Vision runtime использует локальный Unix socket, одну CPU-модель за раз и фиксированные локальные веса. Параметры `--frames-root` и `--session-file` остаются доступны для диагностики; штатные значения — `${PI_HOME}/treed/cam/prints` и `/tmp/treed_cam_session_dir`.

После настройки: `sudo systemctl restart treed-detection.service`; диагностика: `systemctl status treed-detection.service` и `journalctl -u treed-detection.service -n 50`. Не запускать второй экземпляр с `--react` параллельно сервису. Проверка адаптера и реального компонента без устройства: `python -B tools/tests/test_treed_detection.py`.

## Входные параметры

`session_start.sh`:

- имя сессии берется из `arg1`, если не передан — из `PARAMS`;
- вход нормализуется и санитизируется до безопасного имени каталога;
- если итоговое имя пустое, используется `unknown`.

`snapshot.sh` и `session_stop.sh`:

- не требуют входных параметров.

## Контракт интеграции

- Moonraker `shell_command`:
  - `treed_cam_session_start`
  - `treed_cam_snapshot`
  - `treed_cam_session_stop`
- вызов идет из Klipper-макросов через `action_call_remote_method`.

Локальная реакция на результат анализа выполняется компонентом
[`treed_detection`](../../moonraker/components/README.md#назначение-treed_detectionpy).
Он проверяет связанные со сессией JPEG и worker provenance и сам запрашивает
штатный `PAUSE` при подтверждённой серии. Скрипты сессии сохраняют снимки;
`stream_detect.py --react` передаёт свежие видеокадры и метаданные локального worker-а, включая оценку `score` и порог `threshold` для шкалы спагетти в «Камере AI».

## Деплой

- источник: `runtime-scripts/treed-cam/*`
- целевой путь: `${PI_HOME}/treed/cam/bin/*`
- выполняет шаг: `loader/steps/treed-cam.sh`

## Оценка завершённой печати

В каталоге сессии сохраняются исходные JPEG, `session.json` и после оценки `rating.json` с `{sessionId, filename, rating}`. Значения оценки: `good` и `bad`. Видео из кадров скрипты не собирают.

После выбора оценки в UI компонент переносит **всю закрытую папку сессии**:

- «Хорошо» (`good`) → `${PI_HOME}/treed/cam/prints/successful/<sessionId>/`;
- «Плохо» (`bad`) → `${PI_HOME}/treed/cam/prints/failed/<sessionId>/`.

Папки без оценки остаются непосредственно в `prints`. При смене оценки та же сессия
перемещается между `successful` и `failed`; ID, исходные кадры и метаданные сохраняются.
Оценка относится ко всей печати и не служит покадровой разметкой дефектов.

`rating.json` записывается атомарно перед переносом в раздел и служит намерением сортировки.
При смене оценки папка сначала возвращается в корень `prints`: сбой не оставит
новую оценку в противоположном разделе. После сбоя записи прежняя оценка сохраняется,
а повтор запроса восстанавливает соответствующий ей раздел.
API подтверждает сохранение только после переноса. Если перенос не удался, API возвращает
ошибку, данные сохраняются в папке сессии; повтор POST или GET этой сессии завершает
перенос, в том числе после перезапуска Moonraker. Успех GET уже оценённой сессии также
подтверждает размещение в нужном разделе. Одинаковый ID в нескольких разделах,
существующая целевая папка и ссылки приводят к ошибке без перезаписи чужих данных.
Между файловыми системами папки не копируются: ошибка `rename` оставляет исходную папку.

Старые сессии с `rating.json` сортируются при обращении к ним через API;
массового переноса архива нет. Каталоги разделов создаются при первой оценке,
ручная подготовка после обновления не нужна. UI mock имитирует оценку в памяти
и не создаёт папок на компьютере.

Компонент [`treed_print_feedback`](../../moonraker/components/README.md#назначение-treed_print_feedbackpy) выбирает закрытую сессию через `.latest_session` только для завершённого задания с совпадающим полным filename и токеном в runtime-состоянии камеры. Поэтому старый указатель не открывает оценку, если новая печать того же файла уже получила другой токен, но не смогла опубликовать метаданные. Затем UI сохраняет оценку по явно выбранному ID, даже если началась новая печать. Пустая сессия, ручная сессия без токена, старая сессия без метаданных и ошибка JSON недоступны для оценки.

Старт сначала создаёт `/tmp/treed_cam_session_dir.feedback-unavailable` и удаляет прежний `.latest_session`. Marker блокирует оценку, если метаданные нового задания не удалось опубликовать; он снимается лишь после успешного старта метаданных. Stop не переключает `.latest_session`. Поэтому ошибка новой сессии не подставляет прежнюю печать того же файла.

Проверка API и метаданных без Bash: `python -B tools/tests/test_treed_print_feedback.py`.

## Ограничения и замечания

- snapshot endpoint задается через `TREED_CAM_SNAPSHOT_URL` (optional),
  fallback: `http://127.0.0.1:8080/?action=snapshot`;
- optional runtime override-файл: `${PI_HOME}/treed/cam/config/runtime.env`;
- если `PI_HOME` не задан, домашний каталог определяется из пути установки
  скриптов `${PI_HOME}/treed/cam/bin`, одинаково для старта сессии и snapshot;
  имя пользователя `pi` не подставляется, явный `PI_HOME` имеет приоритет;
- интервал warning-throttle задается `TREED_CAM_SNAPSHOT_WARN_INTERVAL_SEC` (по умолчанию `300` сек);
- marker-файл сессии хранится в `/tmp` и сбрасывается после reboot;
- скрипты рассчитаны на fail-safe поведение: не должны валить основной печатный контур.

Адресная проверка путей: `python3 tools/tests/test_treed_cam_paths.py -v`
из корня репозитория на системе с Bash. Проверка использует временные каталоги
и подставной `curl`, не обращается к камере и не меняет активную сессию.

Смежная документация: [диагностика камеры](../../docs/camera.md),
[настройки loader](../../loader/steps/README.md).
